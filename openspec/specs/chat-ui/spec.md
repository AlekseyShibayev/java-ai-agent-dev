# chat-ui Specification

## Purpose
Страница чата в браузере: пользователь отправляет сообщение, видит ответ ассистента по мере генерации, может остановить прогон и понимает, есть ли связь с сервисом.

## Requirements

### Requirement: Открытие страницы чата
Система SHALL отдавать страницу `/chat` с формой ввода и лентой сообщений даже при недоступном OpenCode: недоступность показывается сообщением на странице, а не ошибкой сервера.

#### Scenario: OpenCode выключен
- **WHEN** пользователь открывает `/chat`, а локальный OpenCode API не отвечает
- **THEN** страница отдаётся с кодом 200 и сообщением о недоступности сервиса

#### Scenario: Пустая лента
- **WHEN** пользователь открывает `/chat` без активной сессии
- **THEN** страница показывает пустую ленту и доступную форму ввода

### Requirement: Сессия OpenCode на страницу
Система SHALL создавать сессию OpenCode при первом сообщении страницы и переиспользовать её для последующих сообщений этой страницы.

#### Scenario: Первое сообщение
- **WHEN** пользователь отправляет первое сообщение на свежей странице
- **THEN** система создаёт сессию OpenCode и отправляет в неё промпт

#### Scenario: Следующее сообщение
- **WHEN** пользователь отправляет сообщение после завершения предыдущего прогона
- **THEN** система отправляет промпт в ту же сессию OpenCode и не создаёт новую

### Requirement: Потоковый вывод ответа
Система SHALL передавать в браузер текст ассистента по мере генерации, а не одним блоком после завершения прогона.

#### Scenario: Дельта текста
- **WHEN** в прогоне появляется новая дельта текста ассистента
- **THEN** браузер получает событие с этой дельтой до завершения прогона

### Requirement: Один прогон за раз
Система SHALL допускать только один активный прогон на страницу: повторная отправка во время прогона не создаёт второй промпт, а ввод остаётся заблокированным до завершения или остановки.

#### Scenario: Повторная отправка
- **WHEN** пользователь нажимает Enter, пока прогон активен
- **THEN** второй промпт не отправляется, а ввод остаётся заблокированным

#### Scenario: Прогон завершён
- **WHEN** прогон завершился или остановлен
- **THEN** ввод снова доступен

### Requirement: Остановка прогона
Система SHALL по команде Stop отменять активный прогон и возвращать страницу в состояние ожидания ввода.

#### Scenario: Stop во время генерации
- **WHEN** пользователь нажимает Stop, пока идёт ответ ассистента
- **THEN** прогон отменяется, а страница возвращается в состояние ожидания ввода

### Requirement: Текст ответа не исполняется как HTML
Система SHALL выводить текст модели как текст: разметка экранируется, переносы строк сохраняются.

#### Scenario: HTML в ответе модели
- **WHEN** модель возвращает текст, содержащий HTML-тег
- **THEN** тег отображается как текст и не исполняется браузером

### Requirement: Состояние соединения
Система SHALL показывать отсутствие связи с сервисом и продолжать поток после восстановления соединения без потери уже полученного текста.

#### Scenario: Обрыв потока событий
- **WHEN** поток событий браузера обрывается во время прогона
- **THEN** страница показывает баннер «нет связи»

#### Scenario: Восстановление потока
- **WHEN** соединение восстанавливается
- **THEN** страница убирает баннер и получает пропущенные события прогона

### Requirement: Именованные события браузерного потока
Система SHALL отдавать браузеру именованные события (`text`, `state`, `usage` и другие) с данными прогона, пригодными для отображения, а не сырые фреймы OpenCode.

#### Scenario: Событие текста
- **WHEN** браузер подписан на поток событий прогона
- **THEN** дельта текста приходит как событие `text` с данными прогона
