# Proposal

## Why

Рантайм чата (`chat-runtime`) уже умеет вести прогон над OpenCode API, но проверить его можно только через curl или тесты: у пользователя нет страницы, где видно, как ответ появляется по мере генерации. Без этого не на чем проверять инструменты, permissions и E2E (009).

## What Changes

- MVC-страница `/chat`: форма ввода, лента сообщений, статус соединения, кнопка Stop.
- Первое сообщение страницы создаёт сессию OpenCode, последующие переиспользуют её в рамках страницы.
- Браузерный SSE-endpoint отдаёт именованные события (`text`, `state`, `usage`, …) вместо сырых фреймов OpenCode и replay-ит уже полученные события после переподключения.
- Ввод блокируется на время прогона; повторная отправка не создаёт второй промпт.
- Текст ассистента выводится как текст: HTML экранируется, переносы сохраняются (`white-space: pre-wrap`).
- Stop отменяет прогон и возвращает страницу в idle.
- При недоступном OpenCode страница открывается с сообщением об ошибке, а не с 500.
- Локальные `htmx.min.js` и `htmx-ext-sse.js` фиксированных версий: без CDN.
