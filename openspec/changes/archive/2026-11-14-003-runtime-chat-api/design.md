## Context

См. `proposal.md` — Why. Сейчас `opencode/` умеет отправить промпт и дождаться результата через `/api/session/{id}/message`; потоковых событий и реестра прогонов нет.

## Goals / Non-Goals

- Goals: один читатель SSE на приложение, прогон как подписка с буфером, нормализация частей в DTO.
- Non-Goals: хранение истории прогонов, восстановление после рестарта, UI.

## Decisions

- **Один читатель `/api/event` на приложение, fan-out по `sessionID`.** Альтернатива — соединение на прогон — даёт N подключений к OpenCode и дубли событий.
- **Реестр прогонов в памяти (`ConcurrentHashMap`).** Альтернатива — БД — вне границ 003; история появится отдельной задачей.
- **Дедуп по `(sessionID, durable.seq)` в пределах прогона.** Ключ приходит из OpenCode, поэтому не требует своей нумерации.
- **Виртуальные потоки для чтения SSE** (`spring.threads.virtual.enabled: true`) — блокирующее чтение без ручного пула.
- **Адрес OpenCode разрешается лениво и переспрашивается при ошибке соединения**, кэш — только как подсказка.

## Risks / Trade-offs

- [Потеря событий при рестарте] → прогон закрывается ошибкой, клиент перезапрашивает; восстановление — вне 003.
- [Неограниченный буфер прогона] → буфер ограничен, при переполнении прогон закрывается ошибкой.

## Migration Plan

Новый код в `chat/`; существующий клиент дополняется методами abort и reply. Откат — удаление пакета, внешних изменений нет.
