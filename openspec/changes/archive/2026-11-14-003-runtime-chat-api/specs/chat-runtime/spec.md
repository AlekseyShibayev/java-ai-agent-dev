## ADDED Requirements

### Requirement: Запуск прогона
Система SHALL принимать сообщение пользователя для сессии OpenCode и возвращать идентификатор прогона `runId`, по которому клиент подписывается на события.

#### Scenario: Сообщение принято
- **WHEN** клиент отправляет `POST /api/chat/{sessionId}/messages` с `{text, agent}`
- **THEN** система отправляет промпт в OpenCode и возвращает `runId`

#### Scenario: OpenCode недоступен
- **WHEN** локальный OpenCode API не отвечает на запрос промпта
- **THEN** система возвращает 502 с понятным телом ошибки и не создаёт прогон

### Requirement: Изоляция событий по сессии
Система SHALL публиковать подписчикам прогона только события, относящиеся к его `sessionID`.

#### Scenario: Чужое событие
- **WHEN** из общего потока `/api/event` приходит событие с другим `data.sessionID`
- **THEN** подписчикам прогона оно не публикуется

### Requirement: Дедупликация событий
Система SHALL отбрасывать повторно полученное событие, определённое по паре `(sessionID, durable.seq)`.

#### Scenario: Повтор события
- **WHEN** событие с уже обработанной парой `(sessionID, durable.seq)` приходит повторно
- **THEN** оно не публикуется второй раз

### Requirement: Игнорирование heartbeat
Система SHALL не интерпретировать строки `: heartbeat` из SSE как события.

#### Scenario: Heartbeat в потоке
- **WHEN** в потоке приходит комментарий `: heartbeat`
- **THEN** он не становится событием прогона и не меняет его состояние

### Requirement: Отмена прогона
Система SHALL отменять текущий прогон по запросу клиента и закрывать его статусом `interrupted`.

#### Scenario: Отмена принята
- **WHEN** клиент отправляет `POST /api/chat/{sessionId}/abort`
- **THEN** система передаёт отмену в OpenCode, а прогон закрывается после `session.execution.interrupted`

### Requirement: Ошибка инструмента не завершает прогон
Система SHALL продолжать прогон при событии `session.tool.failed`.

#### Scenario: Инструмент упал
- **WHEN** в прогоне приходит `session.tool.failed`
- **THEN** прогон остаётся активным, а ошибка доступна как часть прогона

### Requirement: Ответ на запрос разрешения
Система SHALL передавать решение пользователя `allow` или `reject` в OpenCode для запроса разрешения прогона.

#### Scenario: Разрешение отклонено
- **WHEN** клиент отправляет `POST /api/chat/{sessionId}/permission/{requestId}` с решением `reject`
- **THEN** система отправляет отказ в OpenCode и прогон продолжается по правилам агента

### Requirement: Нормализованные DTO прогона
Система SHALL отдавать клиенту нормализованные DTO для частей `text`, `reasoning`, `tool` (вход и результат из `content[type=tool]`), а также `usage`, `execution` и `permission`.

#### Scenario: Шаг с инструментом
- **WHEN** в прогоне есть часть `tool` с результатом
- **THEN** DTO содержит вход и результат инструмента в одном виде, независимо от формата события OpenCode

### Requirement: Переразрешение адреса OpenCode
Система SHALL разрешать адрес OpenCode заново при недоступности, не кэшируя его навсегда.

#### Scenario: Сервис перезапущен
- **WHEN** ранее сохранённый адрес OpenCode перестал отвечать
- **THEN** система повторно разрешает адрес и повторяет запрос
