# Proposal

## Why

Страница `/chat` проверяется только MockMvc, шаблонными тестами и HTML-фикстурами. Реальный путь «открыть страницу → отправить сообщение → увидеть ответ по мере генерации → нажать Stop» не прогоняется ни одним тестом: HTMX-обмен, нативная SSE-подписка и busy-состояние композера проверяются руками. Инфраструктура браузерных тестов из 007 (Playwright, случайный порт, артефакты падения) готова, но сценарии чата в ней были отложены в 009.

## What Changes

- Новый браузерный сценарий поднимает приложение на случайном порту и открывает `/chat` без живого OpenCode.
- Модель подменяется стабом клиента OpenCode: сценарий сам решает, когда приходит следующая порция ответа, поэтому «ответ одним куском» не может случайно пройти или упасть из-за тайминга.
- Проверяются: отправка сообщения и появление его в ленте, появление ответа по частям, возврат ввода в idle по Stop.
- Сценарии помечены тегом `e2e` и остаются вне `./gradlew test`.

## Capabilities

### New Capabilities

- `chat-e2e`: браузерная проверка страницы чата от открытия до ответа ассистента без живой модели и без секретов.

## Impact

- Задача: `docs/mini-jira/009-chat-e2e.md` — приёмка и статус.

- Тесты: новые `e2e/ChatPageE2ETest`, `e2e/StubOpenCodeClient`; существующие тесты и `build.gradle` не трогаются.
- Схема БД, публичные ручки API и конфигурация не меняются.
