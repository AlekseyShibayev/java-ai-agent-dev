# Design

## Context

004 даёт работающую страницу `/chat`: Thymeleaf-шаблон, HTMX для отправки и Stop, нативный `EventSource` в `chat.js`. Стилей нет: `static/` содержит только `js/`, разметка лежит в `chat.html`, `fragments/run.html`, `fragments/answer.html`, `fragments/composer.html`. Разметка уже содержит все нужные крючки: `#chat`, `#connection`, `#unavailable`, `#thread`, `.message-user`, `.message-assistant`, `.answer-text`, `#composer`, `#message`, `#send`, `#stop`, `#empty`.

Ограничения: офлайн (без CDN и веб-шрифтов), `build.gradle` не меняется, прод-код ≤ 300 строк, поведение 004 и `chat.js` не трогаются.

## Goals / Non-Goals

**Goals:**
- Один локальный CSS-файл, подключённый со страницы, — без сборки, препроцессоров и фреймворков.
- Внешний вид состояний, которые уже есть в разметке: пузыри, баннеры, busy, фокус.
- Тёмная тема через системную настройку, без переключателя и JS.

**Non-Goals:**
- Маркдаун, подсветка кода, карточки инструментов, usage-панель, permissions.
- Переписывание `chat.js`, изменение контроллеров и фрагментов ответа/композера.
- Шрифты и иконки из сети, анимации появления сообщений.

## Decisions

- **Один `static/css/chat.css` и `<link>` в `chat.html`.** Альтернатива — стили в `<style>` шаблона — не кэшируется браузером и смешивает разметку с оформлением. Spring Boot отдаёт `classpath:/static/**` как есть, тест на `GET /css/chat.css` проверяет именно серверную отдачу, а не наличие файла.
- **Палитра на CSS-переменных в `:root`, тёмная тема — переопределение переменных в `@media (prefers-color-scheme: dark)`.** Так один набор правил обслуживает обе темы, а переключатель не нужен: задача не про настройки пользователя.
- **Индикатор генерации — CSS на `:has(#send:disabled)`**, потому что busy-состояние уже выражено атрибутом `disabled` у кнопки. Это не требует правок `chat.js` (в 004 он в статусе `на ревью`, трогать его в этой задаче нельзя).
- **Скрытие подсказки «Начните диалог» через `#thread:has(article.message) > #empty`**: элемент остаётся в DOM (004 его не удаляет), но не висит над диалогом. Альтернатива — правка шаблона — меняет поведение, а не оформление.
- **Шапка `#app-header` добавляется в `chat.html`** с названием лаборатории: без неё страница начинается с баннера или пустого места. Это единственная правка разметки, тест `ChatMarkupTest` не затрагивается.
- **Композер закреплён `position: sticky; bottom: 0`** внутри `#chat`, отступ ленты снизу — под высоту композера. Альтернатива `position: fixed` требует ручного расчёта ширины и ломается на узком экране.
- **Тест на отдачу стилей — `@SpringBootTest` + `MockMvc`** (как `OpenApiDocsTest`): standalone-setup контроллера статику не отдаёт, а именно серверная отдача — предмет приёмки.

## Risks / Trade-offs

- [`sticky` композер перекрывает конец ответа] → нижний padding ленты больше высоты композера, проверка в браузере на длинном ответе.
- [`:has()` не поддержан в старых браузерах] → целевые браузеры (Chromium из Playwright, актуальные Firefox/Safari) поддерживают; при отсутствии поддержки индикатора и скрытия подсказки не будет, вёрстка не ломается.
- [Два источника переносов: inline `white-space: pre-wrap` в `answer.html` и CSS] → inline оставлен, `ChatMarkupTest` на него опирается; CSS дублирует правило для контейнера целиком.
- [Тёмная тема может ухудшить контраст] → контраст проверяется в браузере, палитра фиксируется переменными в одном месте.

## Migration Plan

Добавляется один файл стилей и `<link>` со шапкой в шаблон страницы; поведение не меняется. Откат — удалить `<link>`, шапку и файл: страница возвращается к дефолтному виду.
