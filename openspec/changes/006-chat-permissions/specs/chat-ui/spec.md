# Spec Delta

## ADDED Requirements

### Requirement: Карточка запроса разрешения

Система SHALL показывать в ленте карточку запроса разрешения с действием и ресурсами, когда прогон получает `permission.asked`.

#### Scenario: Запрос разрешения

- **WHEN** в прогоне появляется `permission.asked` с действием и списком ресурсов
- **THEN** в ленте появляется карточка с этим действием и ресурсами, а прогон остаётся активным

#### Scenario: Разметка в ресурсах

- **WHEN** действие или ресурс запроса содержат HTML-тег
- **THEN** тег отображается как текст и не исполняется браузером

### Requirement: Ответ на запрос разрешения

Система SHALL отправлять решение пользователя allow или reject в OpenCode и не отправлять второй ответ на тот же запрос.

#### Scenario: Разрешение выдано

- **WHEN** пользователь нажимает allow в карточке запроса
- **THEN** система отправляет `allow` для этого `requestId`, а кнопки карточки гаснут

#### Scenario: Повторный клик

- **WHEN** пользователь повторно нажимает allow или reject, пока ответ ещё отправляется или уже отправлен
- **THEN** второй ответ для этого `requestId` не отправляется

### Requirement: Закрытие карточки после ответа

Система SHALL закрывать карточку запроса разрешения после ответа и возвращать ленту к состоянию активного прогона.

#### Scenario: Ответ отправлен

- **WHEN** ответ на запрос разрешения успешно отправлен
- **THEN** карточка закрывается, а состояние ввода и прогона определяется последующими событиями прогона

#### Scenario: Ответ дан в другой вкладке

- **WHEN** в прогоне появляется `permission.replied` для открытой карточки
- **THEN** карточка закрывается без отправки нового ответа из этой вкладки

### Requirement: Устаревший запрос разрешения

Система SHALL показывать сообщение об ошибке и прекращать ожидание ввода, если запрос разрешения уже неизвестен сервису.

#### Scenario: Неизвестный requestId

- **WHEN** пользователь отвечает на запрос, который OpenCode больше не знает
- **THEN** карточка показывает сообщение об ошибке, а её кнопки становятся недоступны

### Requirement: Событие разрешения чужой сессии

Система SHALL не открывать карточку запроса разрешения по событию, `sessionID` которого не совпадает с сессией текущего прогона.

#### Scenario: Чужой sessionID

- **WHEN** в поток прогона попадает `permission.asked` с `sessionID` другой сессии
- **THEN** карточка запроса разрешения в ленте не появляется

### Requirement: Различимые события разрешений

Система SHALL отдавать браузеру разные именованные события для запроса разрешения и ответа на него.

#### Scenario: Событие разрешения

- **WHEN** браузер получает событие разрешения
- **THEN** по имени события он отличает новый запрос от уже данного ответа
