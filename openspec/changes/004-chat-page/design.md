# Design

## Context

Рантайм 003 уже даёт `POST /api/chat/{sessionId}/messages`, `abort` и SSE с именованными событиями по `runId` (`chat-runtime`). Не хватает слоя страницы: сессии OpenCode для браузера, bootstrap-фрагмента после отправки, восстановления потока и разметки. См. `proposal.md` — Why.

Ограничения: без CDN (приложение работает офлайн), `build.gradle` защищён — разрешён только `spring-boot-starter-thymeleaf` и локальные HTMX-файлы, PR ≤ 300 строк кода (вендорные JS не считаются).

## Goals / Non-Goals

**Goals:**
- Один браузерный сценарий: открыть `/chat`, отправить, увидеть дельты, остановить, пережить обрыв.
- Переиспользовать `RunRegistry` и нормализованные `RunEvent`, не дублируя разбор OpenCode.
- Экранирование текста модели гарантирует сервер, а не клиент.

**Non-Goals:**
- История между перезагрузками и несколько страниц/сессий.
- Карточки инструментов, reasoning, usage-панель, permissions (005/006).
- Markdown и подсветка кода.

## Decisions

- **Сессия OpenCode хранится в HTTP-сессии страницы** (`opencodeSessionId`), плюс `runId` активного прогона. Альтернатива — скрытое поле в форме — требует доверия к клиенту и ломает запрет второго прогона.
- **`POST /chat/messages` с контент-согласованием.** При `HX-Request: true` возвращает HTML-фрагмент (сообщение пользователя + контейнер ответа + busy-композер), иначе `202 {runId, sessionId}`. Так контракт `202 + runId` из задачи остаётся тестируемым через MockMvc, а браузер получает серверную разметку без ручной сборки DOM.
- **Второй прогон запрещает сервер:** если прогон сессии в `RunRegistry` активен, возвращается `409`, промпт в OpenCode не уходит. Заблокированный ввод — только отображение этого правила.
- **Свой браузерный endpoint `/chat/runs/{runId}/events`, а не API 003.** Отличия: `id` у каждого события (порядковый номер в буфере прогона) и `after`, вычисляемый из `Last-Event-ID`. Так переподключение не дублирует уже показанный текст. Когда прогон завершён и клиент догнал буфер — ответ `204`: по спецификации SSE браузер прекращает переподключения, иначе завершённый прогон даёт цикл реконнектов.
- **Дельты текста отдаются как экранированный HTML-фрагмент**, который HTMX дописывает (`sse-swap="text"`, `hx-swap="beforeend"` внутри контейнера с `white-space: pre-wrap`). Экранирование делает сервер (`HtmlUtils.htmlEscape`) — модель не может внедрить разметку. Управляющие события (`state`, `usage`) отдаются JSON и обрабатываются небольшим скриптом.
- **Обрыв связи ловится событиями расширения HTMX** (`htmx:sseError`, `htmx:sseOpen`): баннер показывается/скрывается скриптом, переподключение делает `htmx-ext-sse` с `Last-Event-ID`.
- **Stop — это `POST /chat/stop` через HTMX**, возвращает idle-композер; отмена уходит в `ChatService.abort`. Альтернатива — fetch из скрипта — дублирует рендер состояния.
- **При открытии `/chat` дешёвый ping OpenCode** (список сессий); недоступность — баннер на странице, а не 500. Если прогон активен, страница сразу отдаёт контейнер с тем же SSE-endpoint и буфер воспроизводится.

## Risks / Trade-offs

- [Расхождение состояния браузера и сервера при нескольких вкладках] → одна HTTP-сессия на вкладку не гарантируется; в границах задачи вторая вкладка просто делит сессию, 409 защищает от параллельных промптов.
- [HTMX-свап при обрыве может потерять контейнер] → контейнер создаётся сервером до подключения SSE, переподключение не пересоздаёт его.
- [Буфер прогона ограничен] → при переполнении прогон закрывается ошибкой (поведение 003), страница показывает состояние ошибки.
- [Вендорные JS-файлы в репозитории] → фиксированные версии и лицензия в `static/`; обновление — отдельной задачей.

## Migration Plan

Новый пакет `web/` и шаблоны; `build.gradle` получает одну зависимость; существующий API и тесты 003 не меняются. Откат — удаление страницы и зависимости, API продолжает работать.
