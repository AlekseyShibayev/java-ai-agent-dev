# Задачи

Одна задача — один файл `NNN-slug.md` и один change `openspec/changes/NNN-slug/`. Статусы — в `BOARD.md`; исключение `создано`: файл есть, строки в доске нет. В доске только `в работе` и `выполнено`. В `docs/tasks/` только незакрытые задачи; после `закрыто` файл переезжает в `openspec/changes/archive/YYYY-MM-DD-NNN-slug/task.md`.

## Нумерация

Номер задачи неизменяем: это её идентификатор, а не позиция в очереди.

- Номер не меняется никогда: ни при переносе в backlog, ни при возврате, ни при смене приоритета.
- Номера не переиспользуются: закрытая задача не освобождает номер.
- Новая задача — `max(NNN) + 1` по `docs/tasks/` и `docs/tasks/backlog/`, файл добавляется в конец.
- Перестановка существующих файлов и переименование не практикуются.

## Backlog

Задачи, которые не делаются сейчас, лежат в `docs/tasks/backlog/`. Перенос — `git mv`, без правок содержимого и номера. Агент такие задачи в работу не берёт. Возврат в `docs/tasks/` — тоже только `git mv`: `BOARD.md` при переносе не правится, строка появляется, когда задачу взяли в работу.

## Статусы

`создано` → `в работе` → `на ревью` → `закрыто`. Полное правило — `docs/task-statuses.md`; текущие статусы — `BOARD.md`. В файле задачи поля `status` нет.

## Процесс

1. Спека: change `openspec/changes/NNN-slug/` — `proposal`, `specs` (Requirement/Scenario), `design`, `tasks`; `openspec validate --strict --all` зелёный.
2. Тесты по списку (red), затем код (green), затем рефакторинг.
3. Проверка: acceptance закрыт, `./gradlew test` без фильтра зелёный.
4. Взятие задачи, ревью, финиш и архив — по `docs/task-statuses.md`.

Держим только ближайшие задачи; завершённые файлы переносим в `openspec/changes/archive/`, строки из доски удаляем.

## OpenSpec

- Доска держит статус, файл задачи — приёмку (AC), change — поведение и план. Текст не дублируется: AC отвечает «что принять», спека — «как система ведёт себя».
- Один NNN — один change с тем же id; change может ссылаться на несколько NNN.
- Спека — на capability (долговечное поведение), не на этап `plan.md`.
- Язык: текст русский, структурные заголовки и SHALL/MUST — английские.
- Правила записи: `openspec/config.yaml`, навыки — `.agents/skills/openspec-*`.

## Tests (red first)

В задаче обязателен блок — acceptance → имя теста → тип:

```markdown
## Tests

| Acceptance | Test | Type |
| --- | --- | --- |
| read_only не пишет | ReadOnlyRoleTest.shouldRejectInsert | Testcontainers |
```

Имена тестов человек утверждает до реализации. Добавление тестов — норма задачи; изменение существующих — только по явному запросу.
