# Задачи

Одна задача — один файл `NNN-slug.md` и один change `openspec/changes/NNN-slug/`. В `docs/tasks/` только незавершённые задачи; после `done` файл удаляется.

## Нумерация

Номер задачи неизменяем: это её идентификатор, а не позиция в очереди.

- Номер не меняется никогда: ни при переносе в backlog, ни при возврате, ни при смене приоритета.
- Номера не переиспользуются: закрытая задача не освобождает номер.
- Новая задача — `max(NNN) + 1` по `docs/tasks/` и `docs/tasks/backlog/`, файл добавляется в конец.
- Перестановка существующих файлов и переименование не практикуются.

## Backlog

Задачи, которые не делаются сейчас, лежат в `docs/tasks/backlog/`. Перенос — `git mv`, без правок содержимого и номера. Агент такие задачи в работу не берёт.

## Статусы

`draft` → `ready` → `in-progress` → `review` → `done` (или `blocked`).

## Процесс

1. Человек пишет файл, ставит `draft`, затем `ready`.
2. Агент: ставит `in-progress`, коммитит в `main` только файл задачи (в коммите нет ничего другого), затем создаёт ветку `task/NNN-slug`.
3. Спека: change `openspec/changes/NNN-slug/` — `proposal`, `specs` (Requirement/Scenario), `design`, `tasks`; `openspec validate --strict --all` зелёный.
4. Тесты по списку (red), затем код (green), затем рефакторинг.
5. Проверка: acceptance закрыт, `./gradlew test` без фильтра зелёный, человек проверил.
6. `done` → файл задачи удалить, change архивировать (`openspec archive NNN-slug` → `openspec/changes/archive/YYYY-MM-DD-NNN-slug/`). История остаётся в коммитах и PR.

Держим только ближайшие задачи; завершённые удаляем.

## OpenSpec

- Файл задачи держит статус и приёмку (AC), change — поведение и план. Текст не дублируется: AC отвечает «что принять», спека — «как система ведёт себя».
- Один NNN — один change с тем же id; change может ссылаться на несколько NNN.
- Спека — на capability (долговечное поведение), не на этап `plan.md`.
- Язык: текст русский, структурные заголовки и SHALL/MUST — английские.
- Правила записи: `openspec/config.yaml`, навыки — `.agents/skills/openspec-*`.

## Tests (red first)

В задаче обязателен блок — acceptance → имя теста → тип:

```markdown
## Tests

| Acceptance | Test | Type |
| --- | --- | --- |
| read_only не пишет | ReadOnlyRoleTest.shouldRejectInsert | Testcontainers |
```

Имена тестов человек утверждает до реализации. Добавление тестов — норма задачи; изменение существующих — только по явному запросу.
