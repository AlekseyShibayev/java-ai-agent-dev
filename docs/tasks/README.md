# Задания

Задания хранятся в репозитории как Markdown, чтобы их было видно на GitHub, они версионировались вместе с кодом и агент читал их как доверенный вход.

## Структура

```text
docs/tasks/
  README.md              # этот индекс
  _template/             # шаблоны
    task.md
    result.md
    review.md
  001-<slug>/
    task.md              # спека и acceptance-критерии (пишет человек)
    result.md            # отчёт агента: что сделано, команды, вывод
    review.md            # ревью и вердикт человека
```

## Статусы

| Статус | Значение |
| --- | --- |
| `draft` | задача формулируется, брать нельзя |
| `ready` | спека и acceptance-критерии утверждены, можно брать |
| `in-progress` | агент работает |
| `review` | реализация готова, ждёт проверки человеком |
| `done` | проверено и смержено |
| `blocked` | нужна информация или решение |

## Процесс

1. Человек создаёт `task.md` со статусом `draft`, затем переводит в `ready`.
2. Агент берёт задачу: статус `in-progress`, ветка `task/NNN-slug`.
3. Агент реализует и заполняет `result.md`: изменения, команды, вывод проверки.
4. Агент открывает PR `[NNN] <title>` и переводит задачу в `review`.
5. Человек ревьюит дифф, пишет `review.md`, сам запускает проверку.
6. После мержа человек ставит `done` и добавляет ссылку на PR в индекс.

## Правила

- Acceptance-критерии и тесты — собственность человека. Агент не меняет их без отдельной задачи.
- `build.gradle`, CI и существующие тесты — protected paths.
- Задача должна содержать non-goals и список файлов в скоупе.
- Секреты, персональные данные и внутренние адреса в задачи не попадают: репозиторий публичный.
- Одна задача — один PR, желательно ≤ 300 строк.
