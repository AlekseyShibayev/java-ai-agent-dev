# mini-jira

Модуль задач: очередь, статусы и приёмка живут здесь. «Создай задачу X» — значит добавить файл в эту папку.

Одна задача — один файл `NNN-slug.md` и один change `openspec/changes/NNN-slug/`. Статусы — в `BOARD.md`; исключение `создано`: файл есть, строки в доске нет. В доске только `в работе` и `выполнено`. В `docs/mini-jira/` только незакрытые задачи; после `закрыто` файл переезжает в `openspec/changes/archive/YYYY-MM-DD-NNN-slug/task.md`.

## Нумерация

Номер задачи неизменяем: это её идентификатор, а не позиция в очереди.

- Номер не меняется никогда: ни при переносе в backlog, ни при возврате, ни при смене приоритета.
- Номера не переиспользуются: закрытая задача не освобождает номер.
- Новая задача — `max(NNN) + 1` по `docs/mini-jira/` и `docs/mini-jira/backlog/`, файл добавляется в конец.
- Перестановка существующих файлов и переименование не практикуются.

## Backlog

Задачи, которые не делаются сейчас, лежат в `docs/mini-jira/backlog/`. Перенос — `git mv`, без правок содержимого и номера. Агент такие задачи в работу не берёт. Возврат в `docs/mini-jira/` — тоже только `git mv`: `BOARD.md` при переносе не правится, строка появляется, когда задачу взяли в работу.

## Статусы

`создано` → `в работе` → `на ревью` → `закрыто`. Полное правило — `docs/task-statuses.md`; текущие статусы — `BOARD.md`. В файле задачи поля `status` нет.

## Формат файла задачи

Файл задачи — короткий: что просил человек и что принимаем. Как делать — в change.

```markdown
---
id: "NNN"
title: "..."
created: YYYY-MM-DD
branch: task/NNN-slug
pr:
openspec: NNN-slug   # только когда change уже создан
---

## Что сделать

Одно-три предложения: что и зачем, без плана реализации.

## Приёмка

- [ ] Проверяемый результат.
```

- Блоки `Tests`, `Verification`, `Constraints`, `Non-goals`, `Out of scope`, `Depends on` в файле задачи не живут: тесты, план и ограничения — в `openspec/changes/NNN-slug/`.
- Приёмку формулирует человек; агент её не переписывает.

## Процесс

1. Спека: когда задачу берут в работу, заводится change `openspec/changes/NNN-slug/` — `proposal`, `specs` (Requirement/Scenario), `design`, `tasks`; `openspec validate --strict --all` зелёный. До этого change нет, файл задачи несёт только суть и приёмку.
2. Тесты по списку (red), затем код (green), затем рефакторинг.
3. Проверка: acceptance закрыт, `./gradlew test` без фильтра зелёный.
4. Взятие задачи, ревью, финиш и архив — по `docs/task-statuses.md`.

Держим только ближайшие задачи; завершённые файлы переносим в `openspec/changes/archive/`, строки из доски удаляем.

## OpenSpec

- Доска держит статус, файл задачи — приёмку (AC), change — поведение и план. Текст не дублируется: AC отвечает «что принять», спека — «как система ведёт себя».
- Один NNN — один change с тем же id; change может ссылаться на несколько NNN.
- Спека — на capability (долговечное поведение), не на этап `plan.md`.
- Язык: текст русский, структурные заголовки и SHALL/MUST — английские.
- Правила записи: `openspec/config.yaml`, навыки — `.agents/skills/openspec-*`.

## Tests (red first)

Список «acceptance → имя теста → тип» живёт в `tasks.md` change, не в файле задачи:

```markdown
| Acceptance | Test | Type |
| --- | --- | --- |
| read_only не пишет | ReadOnlyRoleTest.shouldRejectInsert | Testcontainers |
```

Имена тестов человек утверждает до реализации. Добавление тестов — норма задачи; изменение существующих — только по явному запросу.
