# Статусы задач

Правило жизненного цикла задачи. Взятые задачи — `docs/tasks/BOARD.md`, файлы задач — `docs/tasks/NNN-slug.md`.

## Что где живёт

- `создано` — только файл задачи в `docs/tasks/`; строки в доске нет.
- `в работе`, `на ревью` — строка в доске.
- находки ревью — под таблицей доски, раздел `## Ревью`; после исправления подраздел задачи удаляется.
- `закрыто` — `openspec/changes/archive/YYYY-MM-DD-NNN-slug/task.md`, в доске строки нет.

## Статусы

| Статус | Кто ставит | Когда |
| --- | --- | --- |
| `создано` | человек | файл задачи написан; агент её не берёт сам |
| `в работе` | агент-исполнитель | задача взята: строка в доске, claim в `main`, ветка `task/NNN-slug` |
| `на ревью` | агент-исполнитель | ветка влита в `main`, задача ждёт ревью |
| `закрыто` | агент-ревьюер | ревью прошло, change архивируется, файл задачи уходит в архив как `task.md` |

## Переходы

- `создано` → `в работе` — агент взял задачу по прямому указанию человека и добавил строку `в работе`.
- `в работе` → `создано` — агент вернул задачу (не хватает данных, нужен человек): строку из доски удаляет, файл задачи остаётся; причина — в комментарии к коммиту.
- `в работе` → `на ревью` — merge ветки в `main`, строка меняется на `на ревью`.
- `на ревью` → `закрыто` — ревью прошло: строка удаляется из доски, change и файл задачи уезжают в архив.
- `на ревью` → `в работе` — ревью не прошло: находки записаны под таблицей доски, исполнитель дорабатывает.
- `закрыто` — терминальный статус; номер задачи не переиспользуется.

## Claim: кто взял задачу

Задача считается взятой, когда это видно в `main` на любом ноутбуке.

1. Агент берёт задачу только по прямому указанию человека; `создано` — не приглашение.
2. Ставит `в работе` в `docs/tasks/BOARD.md` и в колонку `Кто` — свой идентификатор (имя агента из `.opencode/agents/` или логин человека); если строки ещё нет — добавляет её.
3. Переименовывает окно своей сессии в `NNN-slug` — локальная подсказка; владелец задачи — колонка `Кто` в `main`. Нет такой возможности у агента — шаг пропускается, взятие не блокирует.
4. Коммитит в `main` только `BOARD.md` и файл задачи, затем `git push`.
5. Создаёт ветку `task/NNN-slug` и работает в ней.
6. `BOARD.md` в ветке не правится: merge не должен конфликтовать.

Параллельные агенты: если `git push` отклонён, `git pull --rebase`, перечитать строку задачи и повторить. Тот, чей push прошёл, владеет задачей; второй берёт другую.

## Ревью

Ревью делает отдельный агент в чистой сессии — не тот, кто писал код. Человек в цикле не участвует.

Ревьюер проверяет по `main` после merge:

1. Каждый пункт `## Acceptance criteria` в файле задачи — фактически (файл, команда, вывод), а не по словам исполнителя.
2. `./gradlew test` без фильтра — реальный прогон, не «тесты зелёные».
3. `openspec validate --strict --all`, если у задачи есть change.
4. Согласованность с `AGENTS.md`, `docs/task-statuses.md`, `docs/tasks/BOARD.md`, `docs/plan.md`.
5. Секреты в диффе, отсутствие правок в `build.gradle` и существующих тестах.

Вердикт — только две формы: `OK` или `НЕ OK` со списком находок «файл:строка — что не так».

## Финиш

1. Ветка влита в `main` → строка `на ревью`.
2. Ревьюер проверил → строка `закрыто`, change `openspec/changes/NNN-slug/` архивируется (`openspec archive NNN-slug` → `openspec/changes/archive/YYYY-MM-DD-NNN-slug/`), файл задачи переезжает туда же как `task.md` (`git mv docs/tasks/NNN-slug.md openspec/changes/archive/YYYY-MM-DD-NNN-slug/task.md`), затем строка задачи удаляется из `docs/tasks/BOARD.md` тем же коммитом. Если change не заводился, папка архива содержит только `task.md`.
3. Ревью не прошло → строка `в работе`, под таблицей `docs/tasks/BOARD.md` в разделе `## Ревью` появляется подраздел `### NNN — Задача` с находками:

```markdown
### NNN — Задача

- `путь/файл:строка` — что не так и что ожидалось.
```

Файл задачи не правится. Исполнитель исправляет, снова merge → `на ревью` → подраздел удаляется, повторное ревью.

## Backlog

Задачи из `docs/tasks/backlog/` на доску не попадают и статуса не имеют: они не начаты. Агент их не берёт.

Возврат в `docs/tasks/` — только `git mv`: `BOARD.md` не правится, строка не добавляется. Строка появляется, когда задачу взяли в работу; перенос — не взятие.
