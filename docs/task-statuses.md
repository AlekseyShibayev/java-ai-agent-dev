# Статусы задач

Правило жизненного цикла задачи. Текущие статусы — `docs/tasks/BOARD.md`, файлы задач — `docs/tasks/NNN-slug.md`.

## Статусы

| Статус | Кто ставит | Когда |
| --- | --- | --- |
| `создано` | человек | файл задачи написан; агент её не берёт сам |
| `в работе` | агент-исполнитель | задача взята: claim в `main` и ветка `task/NNN-slug` |
| `выполнено` | агент-исполнитель | ветка влита в `main`, задача ждёт ревью |
| `закрыто` | агент-ревьюер | ревью прошло, файл задачи уходит в `docs/tasks/archive/`, change архивируется |

## Переходы

- `создано` → `в работе` — агент взял задачу по прямому указанию человека.
- `в работе` → `создано` — агент вернул задачу (не хватает данных, нужен человек); причина — в комментарии к коммиту.
- `в работе` → `выполнено` — merge ветки в `main`.
- `выполнено` → `закрыто` — ревью прошло.
- `выполнено` → `в работе` — ревью не прошло: находки записаны в файл задачи, исполнитель дорабатывает.
- `закрыто` — терминальный статус; номер задачи не переиспользуется.

## Claim: кто взял задачу

Задача считается взятой, когда это видно в `main` на любом ноутбуке.

1. Агент берёт задачу только по прямому указанию человека; `создано` — не приглашение.
2. Меняет статус на `в работе` в `docs/tasks/BOARD.md`.
3. Коммитит в `main` только `BOARD.md` и файл задачи, затем `git push`.
4. Создаёт ветку `task/NNN-slug` и работает в ней.
5. `BOARD.md` в ветке не правится: merge не должен конфликтовать.

Параллельные агенты: если `git push` отклонён, `git pull --rebase`, перечитать строку задачи и повторить. Тот, чей push прошёл, владеет задачей; второй берёт другую.

## Ревью

Ревью делает отдельный агент в чистой сессии — не тот, кто писал код. Человек в цикле не участвует.

Ревьюер проверяет по `main` после merge:

1. Каждый пункт `## Acceptance criteria` в файле задачи — фактически (файл, команда, вывод), а не по словам исполнителя.
2. `./gradlew test` без фильтра — реальный прогон, не «тесты зелёные».
3. `openspec validate --strict --all`, если у задачи есть change.
4. Согласованность с `AGENTS.md`, `docs/task-statuses.md`, `docs/tasks/BOARD.md`, `docs/plan.md`.
5. Секреты в диффе и отсутствие правок в `.ai/wiki/`, `build.gradle`, существующих тестах.

Вердикт — только две формы: `OK` или `НЕ OK` со списком находок «файл:строка — что не так».

## Финиш

1. Ветка влита в `main` → строка `выполнено`.
2. Ревьюер проверил → строка `закрыто`, файл `docs/tasks/NNN-slug.md` переезжает в `docs/tasks/archive/NNN-slug.md` (`git mv`), change `openspec/changes/NNN-slug/` архивируется (`openspec archive NNN-slug`). Строка в доске остаётся как история.
3. Ревью не прошло → строка `в работе`, в файл задачи добавляется блок:

```markdown
## Ревью

- `путь/файл:строка` — что не так и что ожидалось.
```

Исполнитель исправляет, снова merge → `выполнено` → повторное ревью.

## Backlog

Задачи из `docs/tasks/backlog/` на доску не попадают и статуса не имеют: они не начаты. Агент их не берёт.
