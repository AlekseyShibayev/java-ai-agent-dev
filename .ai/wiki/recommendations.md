# Рекомендации для AI-проектов

Общие правила, не привязанные к конкретному репозиторию. Дополнять по мере необходимости.

## Доступ к базе данных

- Агенту выдаётся отдельная роль **только на чтение** (например, `read_only`).
- Роль приложения с записью и DDL агенту не выдаётся.
- Разрешено: `SELECT`, просмотр схемы, `EXPLAIN` для читающих запросов.
- Запрещено: `INSERT`, `UPDATE`, `DELETE`, DDL, `COPY`, `pg_read_file`, `SET ROLE <app_role>`, вызов функций с побочными эффектами.
- Пароли — только в локальном конфиге вне репозитория: `~/.pgpass` или внешний `application.yaml`.
- Изменения схемы делает приложение через миграции, а не агент.
- Если задаче нужны права на запись — агент останавливается и сообщает, что это должен сделать человек или приложение.

### Проверка

```bash
psql -h <host> -p <port> -U <readonly_role> -d <database> \
  -c "select current_user, current_setting('default_transaction_read_only')"
```

Ожидаемо: `<readonly_role> | on`.

### Почему

Несанкционированная запись или DDL может сломать данные, миграции и воспроизводимость.
Read-only роль с `default_transaction_read_only = on` делает это технически невозможным,
а не только запрещённым на словах.
