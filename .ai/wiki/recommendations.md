# Рекомендации

Правила, которые агент соблюдает по умолчанию. Дополнять по мере необходимости.

## База данных

- Агенту выдаётся только роль с правами чтения: `read_only`.
- Не использовать роль приложения `app` для инспекции или отладки: у неё есть запись и DDL.
- Разрешено: `SELECT`, просмотр схемы, `EXPLAIN` для читающих запросов.
- Запрещено: `INSERT`, `UPDATE`, `DELETE`, DDL, `COPY`, `pg_read_file`, `SET ROLE app`, вызов функций с побочными эффектами.
- Пароль — только через `~/.pgpass` или локальный конфиг вне репозитория.
- Изменения схемы делает приложение через Liquibase changeset, а не агент.
- Если задаче нужны права на запись — агент останавливается и сообщает, что это должен сделать человек или приложение.

### Проверка

```bash
psql -h localhost -p 15432 -U read_only -d devagent \
  -c "select current_user, current_setting('default_transaction_read_only')"
```

Ожидаемо: `read_only | on`.

### Почему

Несанкционированная запись или DDL может сломать данные, миграции и воспроизводимость.
Роль `read_only` с `default_transaction_read_only = on` делает это технически невозможным,
а не только запрещённым на словах.
