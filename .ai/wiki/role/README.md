# Роли

Как работать с агентами в разных ролях. Общие правила, не привязанные к конкретному проекту.

## Когда кого звать

| Роль | Когда | Результат |
| --- | --- | --- |
| Оркестратор | задача больше одного шага или нужны несколько специалистов | план, назначения, сводка и решение |
| Архитектор | до кода: границы, контракты, trade-offs | дизайн/ADR, интерфейсы, риски, план отката |
| Критик | после появления артефакта: ревью, безопасность, пробелы | находки по severity и вердикт |

## Общие принципы

- Один артефакт — один владелец.
- Каждая роль получает полный контекст и критерии готовности.
- Роль не делает работу другой роли.
- Человек принимает решения и несёт ответственность; агент даёт варианты и доказательства.

## Контракт передачи

Перед запуском любой роли зафиксируйте:

```text
Goal:
Inputs:
Constraints:
Done when:
Out of scope:
Budget (время/раунды/токены):
```

Без `Done when` роль будет оптимизировать не то, что нужно.
